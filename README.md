# Aubeig — Bio & Games

Две страницы с общим визуальным языком и настройками:

- **`bio.html`** — портфолио, экосистема проектов, терминальные и чат-предпросмотры.
- **`games.html`** или **`Портал (2).html`** — Blackjack, Slots, Dice и Plinko. Оба имени содержат одну и ту же актуальную сборку, включая автономный тестовый режим.

HTML-файлы содержат встроенные стили, шрифты, иконки и клиентский JavaScript. Читаемые исходники находятся в `templates/` и `assets/`. **Тестовые игры работают даже без сервера**: откройте `games.html`, выберите карточку игры и нажмите «Играть» в панели над доком. Вход не обязателен; сама ставка делается отдельной кнопкой уже за столом. В `file://` и изолированном HTML-просмотрщике локальный режим выбирается автоматически. Сервер нужен только для серверного аккаунта/Telegram и будущей интеграции кошелька.

## Запуск

Для локальной тестовой игры Node.js не нужен. Для серверного режима нужен **Node.js 22.13+** с `node:sqlite`.

```sh
npm ci
npm run build
npm start
```

Открыть:

- `http://localhost:8000/` или `/games.html` — портал;
- `http://localhost:8000/bio.html` — био.

Сервер слушает `0.0.0.0`. В браузерном коде используются только относительные `/api/...` URL: отдельный API-хост или вызовы `localhost` из опубликованной страницы не нужны.

Две страницы независимы: открывайте `/bio.html` и `/games.html` по отдельности. `LANDING_PAGE=bio` меняет корневой маршрут на био, не объединяя страницы.

Готовые HTML уже собраны. `npm run build` нужен после изменения исходников. Редактировать лучше исходники, иначе следующая сборка заменит правки в HTML.

## Что есть в играх

- **Dice:** настоящий шестигранный кубик с точками, результат 1–6. Это не прежний диапазон 0–99. Строгие «меньше / больше», согласованные вероятности и множители.
- **Plinko:** пропорциональное поле с боковыми пинами, вариативные баллистические дуги по маршруту партии, подсветка попаданий, инспектор точного множителя и вероятности, кеш статичного поля; корректное завершение при сворачивании/смене игры. 8/12/16 рядов, три риска, до восьми визуально одновременных шаров. Один анимационный цикл вместо цепочек таймеров. Одна геометрия пинов, отскоков и ячеек; маршрут соответствует рассчитанному результату и переживает resize. Выбор риска/рядов блокируется до окончания падений.
- **Slots:** три независимых равновероятных барабана, одна выплата за спин. Видимая линия соответствует результату партии; смещение задаётся в размерах ячейки, а не устаревающих пикселях.
- **Blackjack:** одна колода 52 карты, S17, Blackjack 3:2, удвоение первых двух карт, корректные тузы и ничьи. Начатая раздача сохраняется и не отменяется с возвратом ставки. Сплит и страховка не реализованы и не предлагаются в интерфейсе.
- История партий, проверка раскрытого seed в браузере, избранное, раскрывающийся островок состояния, звуки с выключенным по умолчанию переключателем, RU/EN, светлая/тёмная темы, стекло, фон, эффекты, цвет стола и reduced motion.

## Баланс и Виолы

**Сейчас включён только отдельный тренировочный счёт.** При первом входе выдаются 1 000 фишек. Нет покупок, депозитов, вывода или подключения к реальному кошельку Виол. Это явно обозначено в интерфейсе.

- Денежные значения API — целые числа в сотых долях фишки (`balanceMinor`, `betMinor`, `payoutMinor`).
- Ставка: целые 5–500 фишек.
- В серверном режиме SQLite хранит пользователей, сессии, партии, журнал проводок и ответы на идемпотентные запросы.
- Серверные изменения баланса, создание партии и фиксация ответа выполняются в одной SQL-транзакции.
- В серверном режиме результат игры никогда не берётся из DOM или `localStorage`. Локальный тестовый счёт существует отдельно и не принимается сервером.
- Повтор одного `actionId` возвращает тот же результат. Другие параметры с тем же ключом отклоняются.
- Клиент сохраняет неподтверждённый запрос и предлагает проверить/повторить **тот же** ключ, не создавая новую ставку.

Граница интеграции: `server/wallet/local.js` и `server/wallet/violas.js`. Второй файл намеренно **не имитирует реальный кошелёк** и не разрешает включить незавершённый провайдер. Для подключения понадобятся правила API Виол, идентификация владельца, единицы суммы, резервирование/списание и идемпотентная выплата. Для внешнего кошелька потребуется устойчивый outbox/состояние расчёта: нельзя заменять SQL-проводку обычным `fetch` внутри транзакции.

Гостевые тренировочные средства не переносятся автоматически в Telegram-аккаунт или реальный кошелёк.

## Telegram

Гость работает без внешних настроек. Для Telegram скопировать `.env.example` в `.env` и заполнить **на сервере**:

```dotenv
PUBLIC_ORIGIN=https://games.example.com
TELEGRAM_BOT_USERNAME=your_bot
TELEGRAM_BOT_TOKEN=
```

Токен вводится только в локальный `.env` или хранилище секретов хостинга. Его нельзя добавлять в HTML, репозиторий или клиентский JavaScript.

1. Привязать публичный HTTPS-домен через `/setdomain` у BotFather для Login Widget.
2. Для Mini App настроить соответствующий HTTPS URL у бота.
3. Перезапустить сервер.

Гостевой вход проверяет созданную сессию перед завершением входа. Поздний ответ стартовой загрузки не может сбросить новый аккаунт. Во встроенном предпросмотре при блокировке cookies доступен отдельный токен вкладки в `sessionStorage` (не в постоянном `localStorage`); HttpOnly cookie остаётся основным способом. Этот fallback включается только явно через `EMBEDDED_PREVIEW=true`. Неподтверждённые игровые запросы изолированы по аккаунтам.

Реализованы два проверяемых формата:

- Login Widget: SHA-256 токена как HMAC-ключ, проверка подписанных полей и `auth_date`; callback привязан к одноразовому состоянию входа и cookie.
- Mini App: HMAC `WebAppData`, проверка `initData`, времени и профиля. Передача происходит после явного действия пользователя, а не автоматического доверия URL.

Подтверждения живут не более пяти минут, повторное использование подписи отклоняется. Имя пользователя не заменяет проверку подписи. Без конфигурации кнопка сообщает о недоступности Telegram, а не создаёт фиктивный Telegram-профиль.

Проверка реального входа с вашим ботом, его доменом и хостингом остаётся этапом настройки. Криптографические проверки покрыты локальными тестами.

Документация протоколов: [Login Widget](https://core.telegram.org/widgets/login), [Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

## Проверяемые результаты

Перед ставкой клиент получает `nextHash` и `nonce`. Запрос содержит ожидаемый commitment и собственный `clientSeed`. Сервер использует HMAC-SHA256 с разделением по игре и nonce, а выбор целого — rejection sampling без modulo bias.

После расчёта раскрывается использованный seed. В Blackjack seed, колода и скрытая карта **не раскрываются до завершения**. Браузерная проверка воспроизводит результат. Это позволяет проверить соответствие commitment и результата, но не является независимым аудитом эксплуатации сервера.

Точные правила выплат доступны внутри каждой игры и в `assets/shared/game-rules.js`.

## Развёртывание

```dotenv
NODE_ENV=production
PUBLIC_ORIGIN=https://games.example.com
DATABASE_PATH=/persistent-data/aubeig.sqlite
TRUST_PROXY=true
WALLET_PROVIDER=local
```

- `TRUST_PROXY=true` — только за своим доверенным reverse proxy; закрыть прямой доступ к Node-порту.
- Проксировать и HTML, и `/api` на один origin. HTTPS обязателен для production.
- Директория БД должна быть постоянной, приватной и резервироваться с учётом SQLite WAL.
- `.env`, БД и журнал сессий не публикуются и исключены из Git. HTTP раздаёт только две страницы и `assets/`, не `server/`, `.env` или `data/`.
- HttpOnly cookies, CSRF-токен, проверка Origin, ограничение запросов и объёма JSON включены.
- `EMBEDDED_PREVIEW=true` использует Secure/Partitioned cookies в HTTPS-встроенном предпросмотре. Для обычного сайта оставить `false`. Telegram лучше проверять в отдельной вкладке на зарегистрированном домене.
- Текущий rate limiter рассчитан на один процесс. Для нескольких инстансов нужен общий limiter и согласованное хранилище. Подключение реальных средств требует отдельной проверки безопасности и бизнес-правил.

## Интерфейс

Общие жидкие стеклянные переключатели (прозрачная линза, блики, SVG-рефракция с CSS-fallback, перетаскивание и пружина) находятся в `assets/shared/controls.css`, раскрывающиеся островки — в `assets/shared/island.js`. Профили `Hyprland` (направленный сдвиг) и `Caelestia` (раскрытие панели) дополняются различающимися контурами Star, Bloom, Orbit, Ribbon, Liquid и Iris. Alt+1…5 переключает разделы; Escape закрывает панели. Системное уменьшение движения имеет приоритет. В интерфейсах нет служебных сообщений о сборках и номерах редизайна.

`index.html` и `жижа.html` сохранены как исходные материалы. Загруженная версия портала архивирована без изменений в `references/portal-original.html`. Файлы `games.html` и `Портал (2).html` теперь всегда собираются вместе и совпадают побайтно — старое имя больше не открывает старую реализацию. Био остаётся отдельным `bio.html`.

- Правила, результаты проверки, проекты, контакты и лицензия оформлены информационными карточками. Исходные условия лицензии сохранены.
- `assets/shared/controls.js` управляет линзой переключателя; `motion-picker.js` и `motion-presets.json` — галереей. В режиме reduced motion пружины/предпросмотр останавливаются, а управление остаётся доступным.

## Тестовая игра без сервера

- `assets/games/practice-store.js` — отдельный браузерный движок для Dice, Slots, Plinko и Blackjack; использует те же правила и выплаты.
- `assets/games/browser-random.js` — переносимый SHA-256/HMAC и rejection sampling. Расчёты совпадают с серверными и проверяются без зависимости от Web Crypto `subtle`.
- Баланс, история и активная раздача сохраняются в `sessionStorage` вкладки. При запрете хранилища остаются в памяти до закрытия страницы. Локальные фишки **не переводятся** в серверный аккаунт или Виолы.
- «Попробовать без входа» доступно даже при зависшем серверном входе. Серверные неподтверждённые ставки не заменяются локальными и не повторяются новым ключом.
- Прелоадер — жидкие часы из исходного `index.html`; не ждёт `/api`, имеет ограничение ожидания и не блокирует страницу при ошибке загрузки.
- Галерея переходов показывает различимый кадр, контур, ползунок 0–100%, открытие/закрытие и замедленное воспроизведение. Для реальных окон и предпросмотра используется общий `motion-recipes.js`.
- Текст мягко раскрывается при загрузке/смене раздела. Inline-плашки и безопасный Markdown (`**жирный**`, `*курсив*`, `код`) оформляют информацию без выполнения HTML из текста.

```sh
npm test
npm run test:browser
npm run test:offline
npm run test:experience
```

`test:offline` проверяет скачанный файл при выключенной сети, sandbox/srcdoc без origin/хранилища и HTTP-страницу с заблокированным API. `test:experience` проверяет прелоадер, анимации текста, плоские стеклянные линзы, различимость контуров, ползунок, оба направления и 320px. Лицензия `@noble/hashes` (MIT) включена в сборки и `assets/licenses/`.

Проверить старое имя файла тем же полным офлайн-сценарием:

```sh
GAME_HTML="Портал (2).html" npm run test:offline
```

Сборочный тест сравнивает оба файла побайтно, чтобы в корне репозитория не появлялся устаревший портал.

## Игровой ритм и темы

- Выбор в коллекции/доке сначала выделяет игру. Только явное нажатие «Играть» в панели над доком открывает стол; ни выбор, ни вход за стол не создают ставку. Прямые hash-ссылки и перезагрузка сохраняют восстановление открытого стола.
- `+ / −` поддерживают удержание мышью, касанием и клавиатурой. Повтор останавливается при отпускании, blur, скрытии вкладки, блокировке ставки и достижении лимита.
- Plinko запускает 1 / 3 / 5 / 8 шаров. До запуска видна полная стоимость. Каждая партия отправляется последовательно со своим idempotency key/nonce. Выход останавливает ещё не отправленные шары, не возвращая уже принятые ставки. При ошибке серия не продолжается автоматически.
- Dice длится 2,1 с; барабаны Slots останавливаются последовательно до 3,05 с. Blackjack раздаёт карты по очереди, отмечает текущий ход, раскрывает закрытую карту и добор дилера. При reduced motion или скрытии вкладки визуал завершается сразу, не меняя результат.
- Постоянная квитанция показывает исход и чистый результат. Дополнительная реакция на поле и ограниченный всплеск частиц не перекрывают управление. Звуковые события различают выбор, ставки, бросок, остановки барабанов, карты, ходы и результаты; по умолчанию звук выключен, громкость задаётся в настройках.
- Светлая тема — самостоятельная зелёно-кремовая палитра, с читаемым игровым сукном. Сакура состоит из SVG и пяти compositor-анимированных лепестков: они останавливаются во время игры/при скрытии вкладки; «Тишина» убирает оформление.
- Переключение «Стекло» меняет и сами линзы/пилюли: в выключенном состоянии нет рефракции, прозрачных бликов и стеклянных слоёв.
- XLI/XGO возобновляются после включения движения, повторяются только при видимости и не сбрасывают интерактивный чат после действий пользователя. Для reduced motion есть кнопка следующего шага. Статусы/иконки обновляются только при смене состояния, а статичное поле Plinko не перерисовывается без изменения геометрии или палитры.
- First Platform отображается неактивным и не открывается. Сведения о шрифте/иконках удалены из окна CPL; сами лицензии сохранены в исходниках.

```sh
npm run test:garden
```

Проверка покрывает выбор до запуска, отсутствие автоматической ставки, удержание, стоимость/отмену серии, длительность и звуковые события, раздачу Blackjack, материальный переключатель, неактивный FP, CPL и живые демо. Исходники изменений разделены на `launch-queue.js`, `blackjack-renderer.js`, `feedback.js`, `sound.js`, `press-repeat.js` и стили `garden.css`/`refinements.css`.
