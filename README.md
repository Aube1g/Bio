# Aubeig — Bio & Games

Две страницы с общим визуальным языком и настройками:

- **`bio.html`** — портфолио, экосистема проектов, терминальные и чат-предпросмотры.
- **`games.html`** — Blackjack, Slots, Dice и Plinko.

HTML-файлы содержат встроенные стили, шрифты, иконки и клиентский JavaScript. Читаемые исходники находятся в `templates/` и `assets/`. Играм нужен запущенный сервер: баланс и результаты не рассчитываются доверенным образом в браузере.

## Запуск

Нужен **Node.js 22.13+** с `node:sqlite`.

```sh
npm ci
npm run build
npm start
```

Открыть:

- `http://localhost:8000/` или `/games.html` — портал;
- `http://localhost:8000/bio.html` — био.

Сервер слушает `0.0.0.0`. В браузерном коде используются только относительные `/api/...` URL: отдельный API-хост или вызовы `localhost` из опубликованной страницы не нужны.

Две страницы независимы: открывайте `/bio.html` и `/games.html` по отдельности. `LANDING_PAGE=bio` меняет корневой маршрут на био, не объединяя страницы.

Готовые HTML уже собраны. `npm run build` нужен после изменения исходников. Редактировать лучше исходники, иначе следующая сборка заменит правки в HTML.

## Что есть в играх

- **Dice:** настоящий шестигранный кубик с точками, результат 1–6. Это не прежний диапазон 0–99. Строгие «меньше / больше», согласованные вероятности и множители.
- **Plinko:** пропорциональное поле с боковыми пинами, вариативные баллистические дуги по серверному маршруту, подсветка попаданий, инспектор точного множителя и вероятности, кеш статичного поля; корректное завершение при сворачивании/смене игры. 8/12/16 рядов, три риска, до восьми визуально одновременных шаров. Один анимационный цикл вместо цепочек таймеров. Одна геометрия пинов, отскоков и ячеек; маршрут соответствует серверному результату и переживает resize. Выбор риска/рядов блокируется до окончания падений.
- **Slots:** три независимых равновероятных барабана, одна выплата за спин. Видимая линия соответствует ответу сервера; смещение задаётся в размерах ячейки, а не устаревающих пикселях.
- **Blackjack:** одна колода 52 карты, S17, Blackjack 3:2, удвоение первых двух карт, корректные тузы и ничьи. Начатая раздача сохраняется и не отменяется с возвратом ставки. Сплит и страховка не реализованы и не предлагаются в интерфейсе.
- История партий, проверка раскрытого seed в браузере, избранное, раскрывающийся островок состояния, звуки с выключенным по умолчанию переключателем, RU/EN, светлая/тёмная темы, стекло, фон, эффекты, цвет стола и reduced motion.

## Баланс и Виолы

**Сейчас включён только отдельный тренировочный счёт.** При первом входе выдаются 1 000 фишек. Нет покупок, депозитов, вывода или подключения к реальному кошельку Виол. Это явно обозначено в интерфейсе.

- Денежные значения API — целые числа в сотых долях фишки (`balanceMinor`, `betMinor`, `payoutMinor`).
- Ставка: целые 5–500 фишек.
- SQLite хранит пользователей, сессии, партии, журнал проводок и ответы на идемпотентные запросы.
- Изменения баланса, создание партии и фиксация ответа выполняются в одной SQL-транзакции.
- Результат игры никогда не берётся из DOM или `localStorage`.
- Повтор одного `actionId` возвращает тот же результат. Другие параметры с тем же ключом отклоняются.
- Клиент сохраняет неподтверждённый запрос и предлагает проверить/повторить **тот же** ключ, не создавая новую ставку.

Граница интеграции: `server/wallet/local.js` и `server/wallet/violas.js`. Второй файл намеренно **не имитирует реальный кошелёк** и не разрешает включить незавершённый провайдер. Для подключения понадобятся правила API Виол, идентификация владельца, единицы суммы, резервирование/списание и идемпотентная выплата. Для внешнего кошелька потребуется устойчивый outbox/состояние расчёта: нельзя заменять SQL-проводку обычным `fetch` внутри транзакции.

Гостевые тренировочные средства не переносятся автоматически в Telegram-аккаунт или реальный кошелёк.

## Telegram

Гость работает без внешних настроек. Для Telegram скопировать `.env.example` в `.env` и заполнить **на сервере**:

```dotenv
PUBLIC_ORIGIN=https://games.example.com
TELEGRAM_BOT_USERNAME=your_bot
TELEGRAM_BOT_TOKEN=
```

Токен вводится только в локальный `.env` или хранилище секретов хостинга. Его нельзя добавлять в HTML, репозиторий или клиентский JavaScript.

1. Привязать публичный HTTPS-домен через `/setdomain` у BotFather для Login Widget.
2. Для Mini App настроить соответствующий HTTPS URL у бота.
3. Перезапустить сервер.

Гостевой вход проверяет созданную сессию перед завершением входа. Поздний ответ стартовой загрузки не может сбросить новый аккаунт. Во встроенном предпросмотре при блокировке cookies доступен отдельный токен вкладки в `sessionStorage` (не в постоянном `localStorage`); HttpOnly cookie остаётся основным способом. Этот fallback включается только явно через `EMBEDDED_PREVIEW=true`. Неподтверждённые игровые запросы изолированы по аккаунтам.

Реализованы два проверяемых формата:

- Login Widget: SHA-256 токена как HMAC-ключ, проверка подписанных полей и `auth_date`; callback привязан к одноразовому состоянию входа и cookie.
- Mini App: HMAC `WebAppData`, проверка `initData`, времени и профиля. Передача происходит после явного действия пользователя, а не автоматического доверия URL.

Подтверждения живут не более пяти минут, повторное использование подписи отклоняется. Имя пользователя не заменяет проверку подписи. Без конфигурации кнопка сообщает о недоступности Telegram, а не создаёт фиктивный Telegram-профиль.

Проверка реального входа с вашим ботом, его доменом и хостингом остаётся этапом настройки. Криптографические проверки покрыты локальными тестами.

Документация протоколов: [Login Widget](https://core.telegram.org/widgets/login), [Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

## Проверяемые результаты

Перед ставкой клиент получает `nextHash` и `nonce`. Запрос содержит ожидаемый commitment и собственный `clientSeed`. Сервер использует HMAC-SHA256 с разделением по игре и nonce, а выбор целого — rejection sampling без modulo bias.

После расчёта раскрывается использованный seed. В Blackjack seed, колода и скрытая карта **не раскрываются до завершения**. Браузерная проверка воспроизводит результат. Это позволяет проверить соответствие commitment и результата, но не является независимым аудитом эксплуатации сервера.

Точные правила выплат доступны внутри каждой игры и в `assets/shared/game-rules.js`.

## Развёртывание

```dotenv
NODE_ENV=production
PUBLIC_ORIGIN=https://games.example.com
DATABASE_PATH=/persistent-data/aubeig.sqlite
TRUST_PROXY=true
WALLET_PROVIDER=local
```

- `TRUST_PROXY=true` — только за своим доверенным reverse proxy; закрыть прямой доступ к Node-порту.
- Проксировать и HTML, и `/api` на один origin. HTTPS обязателен для production.
- Директория БД должна быть постоянной, приватной и резервироваться с учётом SQLite WAL.
- `.env`, БД и журнал сессий не публикуются и исключены из Git. HTTP раздаёт только две страницы и `assets/`, не `server/`, `.env` или `data/`.
- HttpOnly cookies, CSRF-токен, проверка Origin, ограничение запросов и объёма JSON включены.
- `EMBEDDED_PREVIEW=true` использует Secure/Partitioned cookies в HTTPS-встроенном предпросмотре. Для обычного сайта оставить `false`. Telegram лучше проверять в отдельной вкладке на зарегистрированном домене.
- Текущий rate limiter рассчитан на один процесс. Для нескольких инстансов нужен общий limiter и согласованное хранилище. Подключение реальных средств требует отдельной проверки безопасности и бизнес-правил.

Для браузерного теста сервер должен быть запущен. `BASE_URL` меняет адрес; `CHROMIUM_EXECUTABLE` и `CHROMIUM_ARGS` позволяют использовать установленный браузер в ограниченной среде.

## Структура

```text
templates/               HTML-разметка двух страниц и настроек
assets/shared/           настройки, морфинг, DOM, правила игр
assets/games/            UI, визуализация, API-клиент, проверка seed
assets/bio/              портфолио, данные демо и переводы
assets/icons/, fonts/    локальные ресурсы и лицензии
server/                 HTTP, Telegram, SQLite, игровая логика и кошелёк
scripts/build.mjs        сборка двух HTML без CDN-зависимостей
tests/                 математика, баланс, авторизация, API и браузер
```

`index.html` и `жижа.html` оставлены исходными материалами. Изображения из загрузки использованы в карточках игр. Nunito распространяется по SIL OFL, Font Awesome Free — CC BY 4.0; атрибуция встроена в HTML. Исходное авторство контента портфолио и CPL сохранены.

## Интерфейс

Общие жидкие стеклянные переключатели (прозрачная линза, блики, SVG-рефракция с CSS-fallback, перетаскивание и пружина) находятся в `assets/shared/controls.css`, раскрывающиеся островки — в `assets/shared/island.js`. Профили `Hyprland` (направленный сдвиг) и `Caelestia` (раскрытие панели) дополняют четыре материальных перехода. Alt+1…5 переключает разделы; Escape закрывает панели. Системное уменьшение движения имеет приоритет. В интерфейсах нет служебных сообщений о сборках и номерах редизайна.

`Портал (2).html`, `index.html` и `жижа.html` сохранены как исходные материалы. Актуальные сборки — `bio.html` и `games.html`.

## Профили, Виолы и модальные окна

- Изображение `виолы.png` используется через подготовленный прозрачный `assets/games/art/violas.webp`: счёт в островке, ставка, обозначения валюты, профиль и окно счёта. Это оформление **не подключает реальный кошелёк**: средства по-прежнему тренировочные.
- В портале есть профиль с аватаром-монограммой, статистикой, балансом, быстрым запуском игр, историей и копированием ID. В био — отдельное окно профиля Aubeig с контактами, технологиями и переходами к проектам.
- Выбор переходов открыт в отдельной модальной галерее: предпросмотр, клавиатурный выбор, «Применить» и «Отмена». Профили движений общие для двух страниц; звездообразный переход не включён.
- Правила, результаты проверки, проекты, контакты и лицензия оформлены информационными карточками. Исходные условия лицензии сохранены.
- `assets/shared/controls.js` управляет линзой переключателя; `motion-picker.js` и `motion-presets.json` — галереей. В режиме reduced motion пружины/предпросмотр останавливаются, а управление остаётся доступным.

Дополнительная браузерная проверка:

```sh
npm run test:glass
```

Она проверяет drag/click/Space без двойного переключения, применение и отмену анимации, профиль, изображение валюты, вложенные окна, RU/EN, обе темы и 320px. Для тестов гостя внутри iframe сервер запускается с `EMBEDDED_PREVIEW=true`.
