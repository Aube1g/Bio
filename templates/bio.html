04 / Предохранитель

Сначала безопасность. Потом exec.

SafeShell · atomic writes

Опасная команда
не должна пройти.

Перед exec команда проверяется по опасным паттернам: разрушительное удаление, форматирование диска, fork-бомбы и перезагрузка. Отдельно проверяется rm -rf без конкретного пути.

  • Проверка до исполнения, а не после ошибки
  • Запись через временный файл + os.replace
  • Демо показывает блокировку и возврат к точечной очистке

Чёрный список — дополнительный слой, а не гарантия полной изоляции.

SafeShell: Dangerous command blocked.

Self Healing

Авто-ретрай с анализом ошибки через LLM: не слепой повтор, а новый подход с учётом причины сбоя, exponential backoff + jitter.

  • До 3 попыток с изменённым подходом
  • Backoff: base × 2^attempt + случайный jitter
  • Severity: low / medium / high / critical

03 / Память диалога

Меньше токенов. Та же суть.

Длинная переписка сворачивается в рабочее резюме.

Пользователь несколько раз уточняет деплой, переменные окружения, логи и откат. Агенту нужен контекст задачи, а не все повторения.

Пример~3 400tokens

До сжатия / полная история

Пользователь: расскажи про проект, потом уточнял детали по деплою три раза, потом спрашивал про переменные окружения, затем про логи, затем про откат версии…

Один провайдер недоступен? Есть следующий.

Мультипровайдерный fallback переключает запрос дальше по списку. Отдельные таймауты на шаг и на весь агентный цикл не дают сложному запросу обрываться раньше времени.
